# 고입 시기 슬롯 구조 재설계 (설계 스펙)

작성: 2026-07-07
승인: 사용자 승인 완료 (2026-07-07)
선행 문서: `ADMISSION_STAGE_REDESIGN.md` (2026-06-09, 1~5단계 구현 완료 상태에서 본 설계로 개정)

## 배경 및 문제

현재 반별 시트의 접수·결과 기록은 "유형 축"과 "시기 축"이 섞여 있어 입력·판독 시 혼란을 유발한다.

1. 실제접수 칸(V:X)이 영재고·과학고·자사고 3개 유형뿐 — 예술고·마이스터고·외고·일반고 접수는 기록 칸이 없다.
2. 결과 칸(Y:AB, 1차/2차/3차/최종)이 어느 접수 건의 결과인지 연결되지 않는다.
3. 입시_트래킹에 legacy `유형`/`지원학교`와 새 `희망/접수/최종` 컬럼이 공존해 확정값 판독이 어렵다.

실제 행정 절차는 시기 구조다: **영재고(봄, 복수지원 가능) → 전기 1개교 → 후기 1개교(자사·외고·국제고, 불합격 시 일반고 배정)**. 구조를 이 축에 맞춘다.

입력 주체(확인됨): 전기고 접수·합불은 담임 경유로 파악, 후기 일반고 배정은 진학부가 가장 정확히 안다.

## 1. 반별 시트 (301~314) — 담임 입력 영역

H:P 희망 블록은 현행 유지 (설문 자동 유입 포함). V열 이후를 시기 슬롯으로 재편한다.

| 열 | 헤더 | 입력자 | 값 |
|---|---|---|---|
| V | `영재고_접수학교` | 담임 | 학교명 (복수지원 시 쉼표 구분) |
| W | `영재고_결과` | 담임 | 결과 코드 |
| X | `전기_접수학교` | 담임 | 학교명 1개 |
| Y | `전기_결과` | 담임 | 결과 코드 |
| Z | `후기_접수학교` | 담임 | 학교명 1개 (자사·외고·국제고) |
| AA | `후기_결과` | 담임 | 결과 코드 |

**결과 코드** — 한 칸을 단계별로 덮어쓴다:
빈칸(대기) → `1차합`/`1차불` → `2차합`/`2차불` → `최종합`/`최종불` → `포기`

기존 Y:AB(1차/2차/3차/최종) 4칸 구조는 폐기한다.

**유형은 입력하지 않는다.** 학교명 → 유형(영재고/과학고/예술고/마이스터고/특성화고/자사고/외고·국제고/일반고) 자동 분류. 분류 사전에 없는 학교명은 값을 보존한 채 `확인필요` 플래그만 남긴다.

영재고 복수지원: 쉼표 구분 입력 허용. 결과 칸은 최종 진행 중인 학교 기준 1개 값으로 기록한다.

## 2. 입시_트래킹 — 자동 갱신 + 진학부 확정 영역

| 컬럼 그룹 | 원천 | 갱신 정책 |
|---|---|---|
| 희망유형 / 희망학교 | 반별 H:P | 자동 |
| 영재고_접수 / 영재고_결과 | 반별 V:W | 자동 |
| 전기_접수학교 / 전기_유형 / 전기_결과 | 반별 X:Y (유형은 학교명 분류) | 자동 |
| 후기_접수학교 / 후기_유형 / 후기_결과 | 반별 Z:AA (유형은 학교명 분류) | 자동 |
| **최종배정학교** | **진학부 직접 입력** | sync가 절대 덮어쓰지 않음. 후기 일반고 배정 포함, 확정값의 유일한 기록처 |
| 데이터상태 | 자동 판정 | 아래 정의 |

**데이터상태 정의:**

| 상태 | 조건 |
|---|---|
| `미입력` | 희망·접수 모두 없음 |
| `희망만` | 희망만 있고 접수 없음 |
| `영재고진행` / `전기진행` / `후기진행` | 해당 슬롯 접수학교 있음, 최종배정 전 |
| `배정완료` | 최종배정학교 입력됨 |
| `확인필요` | 학교명 유형 미분류, 또는 결과 코드 비표준 값 |

legacy `유형`/`지원학교` 컬럼: 1단계 시트에서 숨김 → 코드 참조 제거 확인 후 삭제 (2단계).

기존 `데이터상태=최종확정` 오염 행(희망값 자동승격 잔재): 마이그레이션에서 최종 관련 컬럼 일괄 클리어 후 새 규칙으로만 채운다.

## 3. 자동화 변경

- `generators/sync_type_to_tracking.py`: `RECEIPT_TYPE_MAP`(유형 3종 고정) 기반 파서를 시기 슬롯 파서로 교체. dry-run 출력을 희망/영재고/전기/후기 슬롯별로 분리 표시.
- 학교명→유형 분류기: `integrated_dashboard.py`에 있는 배정학교타입 분류 로직을 공용 함수로 추출해 재사용 (재구현 금지).
- `generators/generate_final_sheets.py`: "최종=합격" 판정을 새 기준(`*_결과 == 최종합` 또는 `최종배정학교` 존재)으로 교체.
- `generators/build_progress_from_tracking.py`: 집계 기준 컬럼을 새 슬롯 컬럼으로 교체 (현재 8행 과소집계 문제의 해소 지점).
- 반별 시트 읽기를 `batch_get`으로 묶어 호출 수 축소 (쿼터 초과 65초 재시도 제거).
- `integrated_dashboard.py`: 탭 신설 없이 기존 탭의 기준 컬럼 교체 + 각 화면 제목에 "희망 기준/접수 기준/배정 기준" 명시.

## 4. 마이그레이션 순서

기존 데이터는 V:X 14행, Y:AB 10행뿐이라 저비용.

1. 백업 — 기존 `admission_stage` 백업 스크립트 방식 재사용 (로컬 CSV: 📌 메인, 입시_트래킹, 입시 진행 현황, 301~314)
2. 기존 V:X·Y:AB 값을 새 슬롯으로 스크립트 이관 + 육안 확인 (영재고 지원 추정 14건)
3. 301~314 헤더를 새 6칸 구조로 교체
4. 트래킹 최종 관련 오염 컬럼 클리어
5. sync 수정 → 301반 단독 dry-run 검증 → 전체 dry-run → 실제 적용
6. `ADMISSION_STAGE_REDESIGN.md`에 본 설계로의 개정 사실을 진행 기록으로 append

## 검증 (테스트)

- 슬롯 파서 단위 검증: 결과 코드 표준값/비표준값/빈칸, 쉼표 복수 학교, 미분류 학교명 → `확인필요` 판정을 확인하는 최소 테스트 1개.
- 마이그레이션 후 301 단독 dry-run 결과가 이관 전 24행(14+10)과 건수 일치하는지 확인.
- 전체 적용 후 auto_sync 1회 실행: 오류 0건, 진행현황 행 수가 희망 입력 학생 수 규모(수백 행)로 복원되는지 확인.
